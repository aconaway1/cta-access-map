# CLAUDE.md — CTA L access map

Context handoff from a claude.ai chat (2026-10-11). Read this before touching the code.

## What this is

A Cloudflare Worker with static assets: a Leaflet map of every CTA 'L' station (systemwide since 2026-10-11)
showing elevator access, line colors, Loop direction of travel, live elevator outages and step-free alternatives.
Downtown (Loop, West Loop, River North) is hand-maintained and detailed; the rest is generated from open data. Static site +
a small Worker for the API, `*.workers.dev` subdomain, no custom domain, no build step. The owner's older
projects (ronconrails.com, the CML Springfield schedule map) are on Pages, but Cloudflare now treats Pages as
legacy ("applications" are Workers), so this one is a Worker; don't suggest Pages.

Owner: Aaron (network engineer). Prefers direct, technically precise communication.

## Files

- `public/` — the static site (`[assets] directory`; the assets layer serves these before the Worker runs):
- `public/index.html` — page shell, collapsible key panel (auto-collapsed under 600px width)
- `public/style.css` — light/dark via `prefers-color-scheme`
- `public/cta-data.js` — GENERATED by `scripts/build_data.py`; don't edit. `CTA_DATA = {generated, stations, lines}`:
  all 144 stations (id = map ID, name, ll, k, lines, generated `alt`) and GTFS track pieces outside downtown.
- `scripts/build_data.py` — stdlib-only Python; downloads the city L stops dataset and CTA GTFS into `.cache/`
  (gitignored, GTFS is ~70 MB) and writes `cta-data.js`. Rerun after CTA schedule/renovation changes, review
  its "ADA mismatch" notes, commit the output. Reads downtown IDs, names and closures from `app.js`.
- `public/app.js` — `DOWNTOWN` hand-maintained stations (override generated ones by ID, field by field; plus a
  Roosevelt position override), `STATIONS` = merged list, `METRA` downtown stations, `TRACKS` geometry, map setup, pixel-offset track rendering, alert polling (5 min) with stale indicator, step-free alternatives (`alt`), locate-me control (watchPosition; position stays client-side)
- `src/worker.js` — Worker entry; routes `GET`/`HEAD /api/elevators`, 405 for other methods, 404 for anything else
- `src/elevators.js` — `GET /api/elevators`; proxies CTA Customer Alerts API
  (`accessibility=TRUE&activeonly=TRUE`, JSON), normalizes to `{updated, alerts:[{id,headline,short,stations:[{id,name}]}]}`, 120s cache
- `README.md` — deploy and dev commands (`npx wrangler deploy`, `npx wrangler dev`)

CDNs: Leaflet 1.9.4 (cdnjs), leaflet-polylinedecorator 1.6.0 (unpkg), Tabler icons webfont (jsdelivr).
Basemap: Stadia Maps alidade_smooth / alidade_smooth_dark (CARTO now requires an API key). Production
needs the workers.dev hostname registered in the Stadia dashboard. `wrangler.toml` holds name, output dir, compat date.

- West of Tower 18, Green sits beside Pink (d -4 vs +4) and jogs to its Loop offset (-12) between

  failure) the status text turns amber and a warning icon shows in the panel header (visible when collapsed).
  Last good alerts stay on the map. A visibilitychange handler refreshes overdue polls after a phone wakes.
- Stairs-only stations have an `alt` (nearest step-free alternative, including buses for Grand/Chicago Blue,
  whose nearest Blue Line elevators are Clark/Lake and Western). Bus routes checked on transitchicago.com

- `alt` is a list of `[station, detail]` and `bus` a list of `[route, detail]`, rendered as short labeled lists

  repeats the station), and follow the page theme; status colors have separate light/dark text variants.
- Elevator stations also have an `alt`, shown only while they have an elevator alert; the popup status
  switches to amber "Elevator out of service". CTA's alert text never suggests alternatives, but often names
  one platform ("Howard-bound platform elevator"); `ONE_PLATFORM` detects that and notes "Only one platform is
  affected" (no change-direction advice: impossible on one-way Loop lines).
  Neighbor elevator status comes from the city dataset (`8pix-ypme`), e.g. Harrison, Racine and Division (Blue)
  have none.

Systemwide (2026-10-11):
- Stations: city dataset (`8pix-ypme`) for IDs/names/lines/coords; accessibility from CTA GTFS platform
  `wheelchair_boarding` (all platforms `1`), because the dataset lagged renovations: Racine (Blue, elevator since
  Oct 2025) and Austin (Green, Aug 2026) are `ada:false` there. GTFS: 143 open stations, 108 accessible; the
  dataset adds State/Lake (closed, override `k:'c'`). Names get "(Lines)" only when repeated, plus
  ", <branch> branch" for the two Blue Westerns/Harlems.
- Tracks: GTFS shapes clipped to beyond downtown (`keep_point`), crossing points interpolated so pieces meet the
  hand-drawn `TRACKS` exactly; downtown seam points (WEST, ROOSEVELT, N_BRANCH top, Red ends) were moved to GTFS
  positions. Pieces oriented outward with offsets matching the downtown ones (`offset_for`); Red/Blue subway
  stretches just beyond downtown are dashed (`subway`). Everything farther out is drawn solid (no subway info).
- Generated `alt`: along each GTFS trip pattern, nearest accessible station each way (ride semantics hold on
  two-way track), up to six, with distance (grid, or straight line +25% if shorter) and compass direction.
- Popups also offer stations with elevators on OTHER lines (no line in common) when they're closer than every
  listed alternative and within 1.5 mi, up to two (`alternatives()` in app.js, computed at runtime so downtown
  hand lists get it too), e.g. Pulaski (Green) 0.8 mi for Pulaski (Blue), Jackson (Red) ↔ Jackson (Blue).
- Markers shrink at zoom ≤13 (`z-mid`/`z-far` classes); opening view still fits downtown.
- Popup status says "Accessibility alert" instead of "Elevator out of service" when the alert doesn't mention an
  elevator (the feed includes things like "trains will not stop at 43rd").
- Tested: every station within 18 px (z15) of a drawn track of each of its lines (Purple/Orange offsets account
  for most of that), no label overlaps at z16 around any station, no page errors.
- TESTING NOTE: block `tiles.stadiamaps.com` in automated browser runs. A sweep over all stations at z16 loads

## Track geometry and direction (verified)

- Loop rectangle: Lake (N), Wabash (E), Van Buren (S), Wells (W). Corners `NW/NE/SE/SW` in `app.js`.
- Brown: counterclockwise, Outer Loop. Enters/exits at Tower 18 (NW) via Wells.
- Orange, Pink, Purple Express: clockwise, Inner Loop. Orange enters at Tower 12 (SE) from Roosevelt;
  Pink enters at Tower 18 from the west on Lake; Purple at Tower 18 from the north.
- Loop stop orders. `alt` means "use this station instead" (works in either direction), so Loop entries give
  distance + which lines stop there, never "next stop"; a one-way line can't ride back. Every `alt` entry starts with an
  approximate distance (street grid; straight line +15% along diagonal Milwaukee Ave), computed from the city
  dataset coordinates and baked into the strings. Orders, for reference:
  - Brown (outer, CCW): Mart → Washington/Wells → Quincy → LaSalle/Van Buren → HWL → Adams/Wabash →
    Washington/Wabash → (State/Lake) → Clark/Lake → Mart
  - Purple (inner, CW): Mart → Clark/Lake → Washington/Wabash → Adams/Wabash → HWL → LaSalle/Van Buren →
    Quincy → Washington/Wells → Mart. Pink: same loop, entering and leaving via Clinton (Green/Pink).
  - Orange (inner, CW): Roosevelt → HWL → LaSalle/Van Buren → Quincy → Washington/Wells → Clark/Lake →
    Washington/Wabash → Adams/Wabash → Roosevelt
  - Green (both ways): Clinton ↔ Clark/Lake ↔ Washington/Wabash ↔ Adams/Wabash ↔ Roosevelt
- Arrows only on the Loop-circling lines (Brown, Orange, Pink, Purple). Green, Red and Blue run both ways and
  get one line with no arrows, the owner's call (2026-10-11).
- Brown/Purple north branch (`N_BRANCH`): Wells across the river past Merchandise Mart, jog to Franklin at
  Hubbard, north on Franklin past Chicago Ave (map edge ~41.9005).
- Red: subway under State (dashed), north to past Chicago Ave. Blue: subway under Dearborn, west along Congress;
  at-grade in the Eisenhower median west of the river (solid); north end under Lake then northwest under
  Milwaukee past Grand and Chicago.
- `d` in `TRACKS` is a pixel offset to the right of travel direction; `offsetPath()` recomputes miter
  offsets in layer-pixel space on every `zoomend`, and arrow decorators are rebuilt with it.
  Closed paths (first point == last) are handled for the rectangle.
- Coordinates are approximate (hand-placed), good enough for a schematic, not survey-grade.

## Metra (added 2026-10-11, no accessibility data yet)

The six downtown Metra stations are shown as gray square markers for transfers: OTC, Union Station, LaSalle
Street, Millennium, Van Buren Street, Museum Campus/11th St. No tracks, no accessibility status, no alerts.
`ll`/`lines`/colors come from Metra static GTFS (published 2026-10-03), except LaSalle Street, which was moved
south onto the platforms because its GTFS point sits on the CTA LaSalle stations. The opening view still fits
CTA stations only (fitting the Metra Electric stations as well drops a 1400px desktop from zoom 15 to 14).

Researched for the accessibility follow-up:
- Static GTFS is public, no key: `https://schedules.metrarail.com/gtfs/schedule.zip` (check `published.txt`).
  `stops.txt` has `wheelchair_boarding` (196 × `1`, 45 × `0` = unknown, none `2`). It disagrees with Metra's
  elevator list (79th/Chatham, 87th/Woodruff, 103rd/Rosemoor, Grand/Cicero are `0` but have elevators;
  Millennium is `1` while its only elevator is closed until winter 2026–27), so overrides are needed.
- Realtime: `https://gtfspublic.metrarr.com/gtfs/public/alerts` (protobuf, 30s refresh), free key via
  metra.com/developers, Bearer header or `api_token` param. Key requested 2026-10-11, awaiting approval.
  Store it as a Worker secret (`npx wrangler secret put METRA_API_TOKEN`, or the dashboard), never in the
  repo: it's public. Unknown whether elevator
  outages appear in it; there's no accessibility filter like CTA's.
- License (read 2026-10-11; Metra can change it any time): serve data through our own host (the Worker does),
  show last-updated time, state the app isn't affiliated with Metra (footer note in the panel), no Metra
  trademarks/logo. Nothing about AI or how the app is built. Also: "must not modify or delete Data" (filtering
  to elevator alerts is fine; show alert text verbatim and keep our own alternatives visibly separate; label any
  `wheelchair_boarding` corrections as ours), and "must not state or imply that the data is accurate, complete,
  or timely" (say "no elevator alerts in Metra's feed as of …", not "no outages").
- Metra step-free access is mostly level/ramped platforms plus the accessible car's bridge plate, not elevators
  (~30 elevator sites), so "accessible" needs its own key entries.
- GTFS change notice (Oct 2026): trip/service/shape ID formats changing; stop_id not mentioned.
